# 需求书：admin-web 移动端响应式改造（2026-10-17）

> 来源：用户 2026-10-17「admin 的移动端现在做的有点烂，你看看，我的项目都要做响应式的」。
> 本轮只改 **admin-web**（`/root/proj/admin-web`）；其它项目另行排期。

## 0. 硬约束（先读，违反即返工）

- **设计语言**：一律 antd 默认设计语言（默认 token / 组件样式），**不得**引入自建调色板或自定义 token 映射；纯 CSS 用 `--ant-*` 变量。禁 emoji、文案克制、UI 不写技术说明性文案。
- **不许隐藏导航**：窄屏继续用右侧抽屉（`Main.tsx` 既有实现），不得改成汉堡收起或去掉导航。
- `npm run check`（typecheck + eslint + stylelint + check:tokens + 单测）必须全绿；`scripts/check-tokens.mjs` 的旧调色板守卫不得被绕过。
- **构建验证只用独立输出目录**：`npx vite build --outDir /tmp/admin-web-verify --emptyOutDir`。**严禁**裸跑 `npm run build`（会清空并覆盖生产目录 `/var/www/admin`）。部署由 Hermes 负责，你不要动生产目录。
- 不改 `src/api.ts` 的鉴权流程、不动 PWA 的 `sw.js` 缓存语义（除版本常量按规矩提升外）。
- 小步多次提交；英文 conventional commits；不得改 git 身份；不得 push。
- 改前先读 `AGENTS.md` 与 `src/styles/` 的分区注释，勿重排样式分区顺序。

## 1. 实测问题（Hermes 用 Chromium 在 390×844 真机视口量的，逐页数字）

| 页面 | 超屏表格 | 可横滑 | **被裁掉** | 小触摸目标(<40px) |
|---|---|---|---|---|
| 系统 | 2 个（823px） | 2 | 0 | 376 / 376 |
| 文件 | 2 个（747px） | 1 | **1** | 86 / 87 |
| 管理 | 4 个（最大 **1691px**） | 2 | **2** | 20 / 20 |
| 博客 | 2 个（1313px） | 1 | **1** | 21 / 21 |
| 调试 | 0 | — | 0 | 6 / 6（另有 7 处字号 <12px） |

外加：文件页文件名被截断（`backu…`/`blog-g…`/`davbo…`）；顶栏与工具栏按钮统一 32px 高；表格行内图标按钮（「关闭行」「展开行」）仅 **16×16**；调试/管理/Hermes/数据库页有 <12px 文本。

**根因**：表格多数已设 `scroll={{ x: 'max-content' }}`，但**有几张漏设**（文件列表、管理页服务表、博客页列表）→ 窄屏下右侧被父容器 `overflow:hidden` 裁掉且无法横滑；触摸目标偏小是 antd 默认尺寸（32px / 24px 小按钮、`size="small"` 图标钮）在触屏上不达标。

## 2. 目标（可验收的行为）

1. **任何 ≤390px 视口下，表格要么装得下、要么能横向滑动，绝不允许被裁切**：
   - 全仓排查所有 `Table`，缺 `scroll={{ x: 'max-content' }}` 的一律补上；`System.tsx` 带 `y` 的用法保持两者都设；
   - 同时排除「祖先容器 `overflow: hidden` 导致内部无法横滑」的情况（含卡片/`Content`/自定义 wrapper）；
   - 文件列表的**名称列**给足宽度，横滑后能看到完整文件名；不得以截断省略号代替（若确实空间不足，须 `title` 悬浮/长按可见完整名）。
2. **触摸目标达标**（在 `pointer: coarse` / 窄屏下生效，桌面观感不变）：
   - 主要操作（工具栏、行内「重命名/删除/上传/新建」等）：命中区 **≥44×44px**，视觉可维持原尺寸但要有内边距或伪元素扩大热区；
   - 次要图标按钮（表格行内展开/关闭、折叠等）：命中区 **≥32×32px** 且相邻间距 ≥8px；
   - 不得靠缩小组件「腾地方」。
3. **字号**：可见文本 ≥12px，正文/表格内容 ≥13px；数字/等宽度量沿用现有 token。
4. **窄屏信息密度与换行**：工具栏按钮在窄屏换行或收进「更多」，不得挤成一行导致误触；卡片、键值行窄屏单列；长文本（型号、路径、进程名）按需换行或可横滑，不得重叠。
5. **桌面端不得回归**：≥1200px 的既有布局、密度、交互保持不变（改完必须两侧都看）。

## 3. 验收方式（必须自带可复跑的断言）

新增 `e2e/responsive.spec.ts`（Playwright，沿用 `e2e/` 既有配置），至少在 **390×844（iPhone 12/13/14 尺寸）** 与 **768×1024** 两个视口跑主页面（系统 / 应用 / 版本 / 博客 / 管理 / 终端 / 文件 / 通知管理 / 调试），逐页断言：

1. `documentElement.scrollWidth <= clientWidth + 1`（无文档级横向溢出）；
2. 每个**可见** `table`：要么 `table.width <= viewport`，要么存在可横滑祖先（`overflow-x: auto|scroll` 且 `scrollWidth > clientWidth`）——**不允许第三种情况（被裁）**；
3. 可见交互元素（`button/a/[role=button]/input[type=checkbox]/.ant-switch`）的命中区：主要操作 ≥40px、次要图标 ≥32px（用选择器白名单列出「次要」），断言失败时打印元素文本+尺寸；
4. 可见文本字号 ≥12px；
5. 关键页面元素出现（如系统页 CPU 卡、文件页「新建文件夹」按钮），无 `pageerror`。

断言失败信息要能定位（页面名 + 元素文本 + 实际尺寸）。若现有 e2e 与本断言冲突，以本断言为准并说明原因。
